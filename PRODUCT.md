# PProg Viewer — контекст продукта

## Для кого и зачем
Просмотрщик локального TXT-экспорта BOLID PProg для инженеров и техников: приборы, ШС, разделы и группы разделов, реле, выходы, исполнительные устройства и связи.

## Платформы
Единая веб-версия работает как PWA на iPhone, как сайт GitHub Pages и в Android WebView APK. Веб-обновления используют `index.html`, `sw.js` и `version.json`.

## Строгие правила данных
- TXT обрабатывается **локально**. Не загружать реальные конфигурации, адреса или пароли в публичный репозиторий.
- Записи `Реле` и `Выход` различны. Если выход связан с настоящей записью управляющего реле, в пользовательском интерфейсе он показан только как **Реле**; исходные записи в модели остаются.
- СП2 может содержать записи обоих видов. Не определять модель физического устройства по тексту `?сп2`.
- СП4 содержит ИУ, рабочий и исходный выходы, а также концевики; выходы не становятся реле без самостоятельной записи `Реле`.
- Формат подписей: `ШС 5`, ссылка на раздел `Р 5`, отдельные категории `Реле` и `Выходы`.
- Не изменять импорт TXT, экспорт CSV/JSON, локальный кэш, проверку обновлений и Android-мост без регрессионных проверок.

## ШС: физическая ёмкость против привязки (2026-11-11)
- Поле `Число_шлейфов` из `[Типы_приборов]` описывает ёмкость шаблона PProg. Для большинства стандартных приборов оно соответствует доступным ШС, но не всегда — например, «Сигнал-10» имеет 10 физических ШС и 100 дополнительных адресных зон (20–119), а в шаблоне PProg указано 110.
- Для «Сигнал-10» физическая ёмкость — 10, для «С2000-КДЛ/КДЛ-2И» — 127 адресных позиций, для «Сигнал-20/20П/20М» — 20. Для прочих типов используется число из шаблона; если его нет, показывать «—» вместо догадки.
- На карточках приборов и в шапке прибора показывать `physicalLoops`, **не** `device.loops.length`. Вкладки ШС и обычный список «Шлейфы и зоны» должны по умолчанию содержать только записи с непустой привязкой `Раздел`, как `linkedDeviceLoops`/ `activeLoops`.
- `model.loops` и записи исходного TXT сохранять без потерь. Фильтр «Все записи TXT» служит для диагностики, CSV следует текущему фильтру. Не считать `Тип_шлейфа: 0` единственным критерием отсутствия привязки.

## Разделение физических ШС, адресных элементов и принадлежности разделам
По реверс-инжинирингу PProg 3.16.2 (локальные отчёты проекта `02-domain-terminology.md` §6, `04-config-format.md` §8.2, `06-config-schema.md` §5.3 и §9): коды типов приборов стабильно индексируют штатный каталог. Не следует считать `loops.length` физической ёмкостью: для типа 34 «Сигнал-10» экспорт содержит 110 записей на 10 физических шлейфов и 100 дополнительных адресных зон. Тип 9/41/61/81 — семейство КДЛ, 127 универсальных адресов, часть которых могут стать выходами/ИУ. Типы 1/2/11/26 — семейство «Сигнал-20», 20 шлейфов. Для неизвестных устройств в UI берётся `Число_шлейфов` из исходного каталога без гарантий, что оно равно числу физических проводных входов; при отсутствии числа выводится «—». В списках пользователей показываем только ШС с принадлежностью разделам; исходные записи сохраняются для диагностики.
